# V2.3 Screen Awareness Mini Spec

更新时间：2026-07-06

## 背景

当前 V2.3 已有最小屏幕感知链路：桌宠 controls 里有一个 Screen awareness 开关，用户发问时可以把临时截图交给 Vision model，Vision model 缺失时不会把截图退给 Chat model，Electron harness 已覆盖“开关、无视觉模型降级、用户问题使用视觉上下文、proactivityLevel>0 时主动气泡、关闭后不继续使用、raw screenshot 不进 session”。

但这还不是用户预期里的“长期看屏幕”和“自然主动说话”。现有实现更像“开关打开后，下一次互动取一帧临时视觉上下文”。它没有事件驱动的后台观察 journal，没有 searchable timeline，也没有一个可解释的主动触发策略来说明为什么这次该开口、为什么不该开口。

V2.3 的产品边界仍然按产品书执行：小面板只保留一个屏幕感知开关；截图/窗口标题默认不进入长期记忆；采样、保留、过滤等高级策略放在 Settings 或内部默认，不放进桌宠小面板。

## 外部参考

- OpenRecall 采用定期截图，把截图里的文字和图像分析成可搜索历史，并强调本地存储和用户控制：<https://github.com/openrecall/openrecall>
- Screenpipe 的关键做法不是每秒录制，而是监听 app switch、click、typing pause、scroll 等有意义事件；每次 capture 同时拿 screenshot 和 OS accessibility tree，accessibility 不可用时才 OCR；本地 SQLite FTS5 做搜索，并支持 app/window/time 过滤和权限边界：<https://github.com/screenpipe/screenpipe>
- Microsoft Recall 把 pause/resume、app/website/sensitive-info filter、snapshot delete/reset、存储上限和用户 opt-in 放在产品层面，不允许管理员无用户选择地偷偷启用：<https://support.microsoft.com/en-us/windows/retrace-your-steps-with-recall-aa03f8a0-a78b-4b3e-b0a1-2eb8ac48701c>
- Memento Native 是 macOS 本地 timeline memory：ScreenCaptureKit + Vision OCR + SQLite FTS5 + on-device embeddings；它提供 capture interval、retention、storage cap、private/incognito auto-pause、manual pause/resume：<https://github.com/owgit/memento-native>
- 早期 Memento/Rewind 风格的低门槛方案是固定间隔截图、OCR、SQLite/vectordb/FTS5，再用 LLM 查询 timeline；这种方式简单但存储和隐私压力更高：<https://github.com/apirrone/memento>

结论：Greyfield 不应该做默认持续高频截图，也不应该把屏幕内容直接塞进长期记忆。更合适的路线是 event-driven observation journal：优先拿轻量文本/窗口/状态信号，只在用户问或变化足够大时走截图和 Vision。

## Open-LLM-VTuber 与 AIRI 实现参考

Open-LLM-VTuber 当前更接近“媒体流常开，触发时抓一帧”的最小产品实现：

- 前端用 camera/screen `MediaStream` 保持可采集状态，真正发送给模型前才 `ImageCapture.grabFrame()` 抽帧、压缩成 JPEG data URL。
- 用户发文字/语音时会调用同一条 `captureAllMedia()`，把摄像头和屏幕帧作为 images 随本轮输入发到后端。
- 主动说话是 idle timer：AI 进入 idle 后，若 `allowProactiveSpeak` 开启，等待 `idleSecondsToSpeak`，再抓取当前媒体帧并发送 `ai-speak-signal`。
- 后端把 `ai-speak-signal` 转成 proactive prompt，并打上 `skip_memory` / `skip_history`，所以主动说话默认不污染记忆和本地聊天历史。
- 视觉输入进入普通 LLM message parts：文字提示加 `image_url`，没有独立 observation store，也没有长期屏幕索引。

这说明：如果 Greyfield 只想先修“主动说话没成功”，可以先做一个 idle/fresh-frame trigger，不必马上做完整长期读屏。

AIRI 当前更接近“视觉模块产出上下文，聊天 runtime 消费上下文”的架构：

- `electron-screen-capture` 封装 Electron desktopCapturer/displayMedia source 选择，并用短 mutex/timeout 控制一次 capture source 使用窗口。
- vision processing store 有 ticker：默认 3000ms capture interval，避免并发 processing，记录 tick/capture/context update 指标。
- vision orchestrator 对每帧跑指定 workload，成功后可发布 `context:update`，内容包含 vision text 和可选 image content，context id 由 workload/source 稳定生成。
- core-agent 有 `ContextRegistry`，按 source bucket 执行 `replace-self` / `append-self`；聊天组 prompt 时把 active contexts 渲染成 `[Context]` bullet 追加到最新用户消息。
- 这条链路是 runtime context，不等于长期记忆；它适合把 Minecraft、vision、工具状态等模块信号统一接入 prompt。

这说明：Greyfield 的长期读屏不应该只照 Open-LLM-VTuber 的 idle 抽帧做到底。更稳的路线是先借 AIRI 的 context registry/ticker 思路，把屏幕 observation 变成可替换、可过期、可观测的 runtime context，再决定哪些内容进入长期 observation journal。

## 用户体验

用户只需要理解一个模式：Screen awareness。

打开后，Greyfield 可以：

- 回答“你看我屏幕上是什么”这类用户主动问题。
- 在 proactivityLevel 允许、画面变化有意义、且近期没有打扰用户时，轻轻说一句和屏幕相关的主动话。
- 在 Settings 中查看和清理屏幕感知保留策略；默认不把截图当长期记忆。

关闭后，Greyfield 必须：

- 立刻停止后续 capture 和视觉上下文使用。
- reload 后仍保持关闭。
- 不用之前保留的 raw frame 偷偷回答新问题。

## 架构策略

### 两条上下文通道

1. Foreground visual context
   - 用于用户主动问屏幕、桌宠刚收到一条含“看屏幕/截图/这是什么”的问题。
   - 获取最新一帧 screenshot，加上可获得的 accessibility/window metadata。
   - 走 Vision model 槽位，不回退给 Chat model。
   - 默认只在本轮 runtime payload 中存在，不进 session、export、memory atom。

2. Background observation journal
   - 用户显式打开 Screen awareness 后才启动。
   - 不保存 24/7 原始视频；默认保存派生信息：timestamp、app/window、capture reason、accessibility text digest、OCR/vision summary、hash、sensitive/private flags。
   - raw screenshot 只允许短 TTL debug/cache；长期保留必须单独设置和可删除。
   - observation journal 和 long-term memory atoms 分开。只有用户显式“记住这个”或后续设置允许的高置信规则，才把屏幕事件转成长期记忆候选。

### 采样策略

优先级从低成本到高成本：

1. Interaction model：聊天意图、桌宠状态、当前模式、最近用户操作、proactivityLevel。
2. OS metadata：active app、window title、URL/domain、idle state、screen lock/private/incognito/video/fullscreen flags。
3. Accessibility tree：按钮、标题、文本字段、选中内容。
4. OCR：accessibility 不可用或变化很大时才跑。
5. Vision model：用户主动问、proactive candidate 需要理解画面、或 OCR/accessibility 不足时才跑。

触发 capture 的事件：

- app/window 切换。
- click/scroll 后静止一小段时间。
- typing pause。
- accessibility text 或 frame hash 与上一条差异超过阈值。
- idle fallback，低频补一条“仍在同一上下文”的 heartbeat。

去重和冷却：

- perceptual hash 或截图 hash 相同则只增加 duplicate count。
- 同 app/window/text digest 连续命中时合并成一个 span。
- Vision/LLM 调用有全局频率上限和 per-app cooldown。

### 主动说话策略

主动屏幕感知不是“每看到一点变化就说话”。必须同时满足：

- Screen awareness 开启。
- `proactivityLevel > 0`。
- Vision model 配置完整，或当前 observation 的文本摘要已足够。
- 最近 observation 足够新，且不是 private/sensitive/filtered。
- 用户没有正在输入、没有刚发消息、没有正在播放 TTS 或处理中。
- 距离上次主动发言超过 cooldown。
- observation scorer 判定“对陪伴有价值”：例如用户停在报错、反复切换同一个任务、屏幕出现用户刚问过的主题、或视觉内容与近期对话/记忆强相关。

输出形式：

- 桌宠气泡优先，短句、低打扰。
- 不自动把这句话写进聊天历史，除非现有 proactive bubble 机制需要记录事件；即使记录，也不能带 raw frame。
- 如果不满足条件，要有 debug/harness 可见的 skip reason：disabled、quiet-level、vision-missing、stale-observation、cooldown、private-filter、low-score。

## 数据模型草案

`ObservationRecord`：

- `id`
- `createdAt`
- `endedAt?`
- `source`: `screen-awareness`
- `captureReason`: `manual-question | app-switch | click-pause | typing-pause | scroll-pause | idle-fallback | proactive-check`
- `appName?`
- `windowTitle?`
- `urlHost?`
- `textDigest`
- `accessibilityText?`
- `ocrText?`
- `visionSummary?`
- `frameHash?`
- `sensitive`: boolean
- `private`: boolean
- `filtered`: boolean
- `rawFrameRef?` only when short TTL cache/debug is enabled

`ObservationJournalStore` 最小版本可先用 JSONL，后续再迁 SQLite FTS5。先做 JSONL 的原因是当前 Electron sqlite 原生模块还有 ABI/打包风险，不能把 V2.3 体验绑在 native sqlite 上。

## Settings 策略

小面板只保留一个 Screen awareness 开关。

Settings 可以放：

- Screen awareness 总开关状态说明。
- Retention：仅派生文本保留天数，默认短期；raw frame cache 默认关闭或极短 TTL。
- Excluded apps/sites/windows。
- Sensitive/private auto-pause。
- Delete observation journal。
- Debug：最近 skip reasons、最近 observation record，不展示 raw screenshot，除非 debug raw cache 明确打开。

## 验收看护

现有 `pnpm harness:electron:visual-observation` 继续保留，并扩展：

- 默认 off，controls 只有一个 Screen awareness toggle。
- 打开后用户主动问题使用 Vision model 槽位。
- Vision model 缺失时给低打扰 notice，不把截图发给 Chat model。
- `proactivityLevel > 0`、fresh observation、meaningful change 时出现主动 screen-aware bubble。
- `proactivityLevel = 0` 不主动说话。
- 关闭后停止 capture/use，reload 后不恢复。
- raw screenshot 不进 session、memory、export。
- observation journal 只保存派生文本/metadata；delete journal 后查询为空。
- private/sensitive/filtered observation 不触发主动说话。
- 每次 proactive skip 有机器可读 reason。

新增 unit tests：

- observation scheduler event dedupe。
- stale observation 不进 prompt。
- cooldown 阻止连续主动发言。
- app/window filter 生效。
- raw frame TTL cleanup。

## 最小下一步

V2.3 下一块不要直接做“长期读屏大系统”。先做一个可落地的 corrective slice：

1. 给 `ObservationController` 增加 scheduler 接口：event-driven trigger + idle fallback + cooldown，不改变 controls UI。
2. 引入 JSONL `ObservationJournalStore`，只写 metadata/text digest/summary，不写 raw dataUrl。
3. 让 proactive screen awareness 从 journal/fresh observation 取候选，并输出 skip reason。
4. 扩展 Electron harness 证明：主动说话来自真实 observation update，而不是手工 `triggerProactiveCheck` 的偶然路径；关闭后 scheduler 停止；journal 可删除。

## 不做什么

- 不默认后台持续截图。
- 不做高频视频录制。
- 不把 raw screenshot 写进长期记忆、session 或 export。
- 不在小面板增加 Shot/Clear/End/preview/frequency 控件。
- 不把缺失 Vision model 的截图交给 Chat model。
- 不做无人值守电脑操作。
